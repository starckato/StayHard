T1-4 PROTOTYPE

Toast Undo 버튼

실수 되돌리기 — 식단/운동/루틴 체크 직후 5초 안에 undo. 인프라 (score-events cancel 액션) 는 이미 완비, UI 만 추가.

① 현재 → 신규
BEFORE
근력 운동 완료 +30
AFTER
근력 운동 완료 +30
차이: 우측에 1px 디바이더 + 빨강 강조 텍스트 버튼. 하단 2px progress bar 가 5초 카운트다운. 시각 무게는 거의 동일, 너비만 약 60px 증가.
② 짧은 메시지 — 식단 체크
클린 식단 +10
③ 긴 메시지 — wrap
3일 연속 기록 달성. 흐름을 지키는 중.
④ 에러 / 정보성 — undo 없음 (현재 그대로)
저장 실패 — 네트워크 확인
원칙: undo 버튼은 되돌릴 수 있는 액션 에만. 저장 실패 / 정보성 ("3일 연속") / 다음 단계 안내 는 기존 단순 toast 유지.
⑤ 동작 사양
표시 기간
5000ms (현재 2000ms 의 2.5배 — undo 누를 시간 충분)
버튼 클릭
해당 액션의 _cancel score event 실행 + toast 즉시 dismiss
자동 dismiss
5초 후 자동 사라짐 — undo 안 누르면 액션 확정
큐 처리
다음 toast 가 오면 현재 undo 가능 toast 는 즉시 dismiss + 확정
적용 대상
workout/cardio done · diet 추가 · routine done · target done · cheat 사용
제외 대상
저장 실패 · 권한 거부 · 정보성 메시지 · 점수 차감 알림
API
showToast(msg, {undo: () => addScore('workout_done_cancel')})
⑥ 적용 예시 (호출부)
// Before
addScore('workout_done', '근력 운동 완료');

// After — 5초 안에 되돌리기 가능
addScore('workout_done', '근력 운동 완료', {
  undo: () => addScore('workout_done_cancel', '근력 운동 취소')
});
⑦ 검토 포인트
• 버튼 카피: "되돌리기" vs "취소" vs "다시" — 선택?
• Progress bar 표시 여부 — 부담스럽지 않은지?
• 5초 충분한지? 7초로 더 길게? 3초로 더 짧게?
• Undo 후 보낼 토스트 — 별도 "취소됨" toast vs 무음?
• 빨강 (var(--accent)) 버튼 톤 OK 인지, 아니면 무채색이 더 단단한지?
• 점수 차감 액션 (식단_금지 -30 등) 도 undo 가능하게 할지?
